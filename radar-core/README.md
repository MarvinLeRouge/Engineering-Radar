# radar-core

Shared data model (SQLModel) and Alembic migrations for [Engineering-Radar](../README.md).

`radar-core` defines the persistence layer shared by every other package:
`Repository`, `Audit`, `MethodologyVersion`, `Category`, `Criterion`,
`ToolResult`, `Finding`, `Evidence`, `Score`, `Recommendation`,
`ImprovementTask`, `RoadmapItem`, and `Snapshot`. See
[`docs/quality-framework.md`](../docs/quality-framework.md) for the
methodology these tables encode, and
[`docs/architecture/radar-core_architecture.md`](../docs/architecture/radar-core_architecture.md)
for the schema design.

Recent additions worth knowing:

- `Criterion.implemented`: synced by `radar-audit` on every score from its
  normalizer registry.
- `Finding.fingerprint` (carries the human verdict, status and note across
  re-audits), `Finding.magnitude`, `Finding.verdict_note` (200 characters at
  most).
- `ImprovementTask` and `RoadmapItem`: filled by `radar-audit` scoring, which
  promotes findings into tasks.
- `observability.py`: `configure_logging` (structlog, `RADAR_LOG_LEVEL`,
  `RADAR_LOG_FORMAT`) and `init_error_tracking` (Sentry, `SENTRY_DSN`,
  `SENTRY_ENVIRONMENT`), shared by `radar-api` and `radar-audit`.
- `Snapshot` exists but nothing writes it yet.

## Prerequisites

The database is SQLite by default, addressed through `RADAR_DATABASE_URL`.

    export RADAR_DATABASE_URL="sqlite:///$(pwd)/radar.db"

## Applying migrations

    uv run --package radar-core alembic -c radar-core/alembic.ini upgrade head

## Creating a new migration

    uv run --package radar-core alembic -c radar-core/alembic.ini revision --autogenerate -m "<short description>"

Review the autogenerated migration before committing it: Alembic's
autogenerate does not always capture every constraint or index correctly.

## Running tests

    uv run --package radar-core pytest
